# Security

## How CC Agent is meant to run

CC Agent is a self-hosted app that starts Claude Code sessions on your computer, as your user. Keep these facts in mind:

- **A full-access agent can do whatever you can do** on that machine: read and change your files, run programs, use your network. Give full access only to agents you would trust with your terminal.
- **Messaging plugins stay with you, not your agents.** Claude Code's official Discord channel plugin runs a bot with your token; if it is installed on the host, an agent that loaded it would act as that bot. CC Agent therefore switches it off for its agents (it writes `"enabledPlugins": {"discord@claude-plugins-official": false}` to `.claude/settings.local.json` in the agent's workspace and in the git repositories above it) and refuses `/plugin enable` for it from the chat. Other plugins you install are loaded by full-access agents as usual: review them with the same care.
- **Scoped agents** can read and write only the folders you allow, and load only the local MCP servers you tick (an agent you give another member uses only the claude.ai connectors you tick, too). They run in Claude Code's auto mode, so they may decide for themselves to fetch web pages: the domains you list are approved in advance, and the sandbox holds Bash's network access to those domains. They run with Claude Code's sandbox and permission rules, and CC Agent writes their settings itself and refuses grants that would reach its own data. This narrows what an agent can do; it is not a guarantee. Treat an agent that reads untrusted content (web pages, email, outside chats) as able to be talked into things.
- **The server listens on 127.0.0.1 only.** To reach it from other devices, put it behind HTTPS and set `CC_AGENT_PUBLIC_ORIGIN`. Don't expose the port directly.
- **Use Cloudflare Tunnel, or a proxy that behaves like it.** Sign-in rate limits and lockouts are counted per visitor address, which CC Agent reads from the `CF-Connecting-IP` header on connections from this machine, and it refuses `/bridge` requests that carry Cloudflare's forwarding headers. If you use another reverse proxy, make it **overwrite** `CF-Connecting-IP` with the real client address (never pass through a value the visitor sent) and block `/bridge` from outside. Otherwise a visitor can dodge the sign-in limits by sending made-up addresses, or every visitor counts as one address and one person can lock everyone out.
- **The peer link trusts a whole machine.** Pairing two installations (docs/PEER-LINK.md) lets the agents you open on both sides exchange messages over SSH. The name of the sending agent is only what the other machine says; your own side's switches and ticks decide what gets in. Use a dedicated SSH key restricted to `scripts/peer-exchange.mjs`, and keep it and `~/.config/cc-agent/peer-key` away from agents.
- **Accounts are the front door.** Change the generated `admin` password on first sign-in, and turn on two-step sign-in or add a passkey. Members cannot create full-access agents. Demoting an admin to a member signs that account out everywhere, stops its full-access agents and takes their full access away; its other running agents restart under a member's rules.
- **Sign-in limits count per account too.** Besides the per-address blocks, 20 wrong passwords on one account name within an hour, from any addresses, or 10 wrong two-step codes in a day, mean that name signs in with a password only from networks it used in the last 30 days, for an hour (a day if it happens again). Whoever guesses cannot lock the owner out: the owner's own networks and QR sign-in stay open.
- **Locked out of your own install?** On the computer CC Agent runs on, `node scripts/sign-in-rescue.mjs` turns off an account's two-step sign-in (`two-step <username>`), lifts an account's protection (`protection <username>`) or lifts an address's block (`block <ip address>`). It leaves a note the server acts on at its next start; restart within a day. It needs only access to that computer's files, which a full-access agent has too: one more reason to give full access with care.
- **Never run the live service with `CC_AGENT_DEV=1`.** It makes the dev server's and test instance's ports on this machine trusted origins, so any program serving a page there could act as a signed-in account. CC Agent only takes it from the command line and ignores it in `server/.env`.
- **Where your data lives.** Accounts, conversations, attachments, secrets and push keys are in `.local/` inside the project folder (or the folder `CC_AGENT_DATA_DIR` names). The request audit log, with visitor addresses and request paths, is in `server/logs/`, or in `logs/` inside the data folder when `CC_AGENT_DATA_DIR` is set. Each agent's full Claude Code transcript is kept by Claude Code in `~/.claude/projects/`. Keep all three out of backups you share, and never commit them.

## Reporting a vulnerability

Please do not open a public issue for a security problem. Email SECURITY_CONTACT_EMAIL instead, with steps to reproduce and the version you saw it in (Settings, at the bottom of the page).

We will acknowledge the report, work on a fix, and credit you in the release notes unless you prefer otherwise.
